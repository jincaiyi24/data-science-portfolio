# EV SQL 面试问答

共 50 题。回答均基于本项目实际结构和结果。

## 1. 为什么选 MySQL 而不是只用 pandas？

**核心回答：** pandas 适合建模前处理，MySQL 更适合关系约束、共享查询、BI 接入和可审计结果。

**深挖追问与回答：** 若数据只有几千行且无共享需求，数据库收益会降低。

## 2. 四张表为什么不合并？

**核心回答：** 四类数据更新节奏、含义和粒度不同，拆表减少重复并防止模型字段污染原始特征。

**深挖追问与回答：** 在线服务若追求低延迟，可建立经验证的宽表或物化视图。

## 3. 为什么 id 可以做单列主键？

**核心回答：** 实测训练 id 为 0-668664、测试 id 为 668665-955235，全集无重叠。

**深挖追问与回答：** 若不同批次会重复 id，应改为 source_set + id 复合主键。

## 4. OOF 预测是什么？

**核心回答：** 每个训练样本的预测都来自未见过该样本的折模型，可用于无泄漏评估与训练集业务排序。

**深挖追问与回答：** 它仍依赖折分设计；时间数据应使用时间切分。

## 5. 为什么测试集 target 是 NULL？

**核心回答：** 测试标签未知，NULL 表示事实缺失；写成 No 会制造错误标签并扭曲 KPI。

**深挖追问与回答：** SQL 聚合时必须明确训练集过滤。

## 6. 最终模型和分群模型为什么不同？

**核心回答：** 最终模型追求竞赛 AUC，分群模型强调基础特征和稳定可解释性；两条轨道均有既有证据。

**深挖追问与回答：** 上线时应建立模型治理，明确每个分数的 owner 和用途。

## 7. 十分位 1 为什么代表最高？

**核心回答：** 业务通常把 Top Decile 作为优先触达群，因此降序排名后把最前 10% 标为 1。

**深挖追问与回答：** 必须在数据字典注明方向，避免仪表盘误读。

## 8. 如何证明没有漏装数据？

**核心回答：** 本地与数据库行数一致、id 唯一、预测和分群连接覆盖率为 100%，并输出验证表。

**深挖追问与回答：** 还可加入哈希总计或抽样逐行比对。

## 9. 为什么用外键？

**核心回答：** 保证预测和分群不能脱离客户存在，减少孤儿记录。

**深挖追问与回答：** 超大批量装载时可先 staging，再在交换前验证约束。

## 10. 为什么要索引 source_set？

**核心回答：** 大量查询只分析训练或测试集合，source_set 是高频过滤字段。

**深挖追问与回答：** 它基数低，优化器可能对全量聚合仍选择扫描。

## 11. 联合索引顺序如何定？

**核心回答：** 按高频过滤前缀和排序需求决定，例如 source_set + prediction_decile。

**深挖追问与回答：** 索引不能同时完美服务所有查询，要用 EXPLAIN 和真实负载验证。

## 12. 什么是覆盖索引？

**核心回答：** 查询所需列全部在索引中，可减少回表。

**深挖追问与回答：** 本项目聚合需要很多列，盲目做宽覆盖索引会增加写入成本。

## 13. CTE 的价值是什么？

**核心回答：** 把连接或派生逻辑命名一次，提高主查询可读性和复用性。

**深挖追问与回答：** MySQL 优化器可能合并或物化 CTE，应通过 EXPLAIN 判断。

## 14. 窗口函数和 GROUP BY 区别？

**核心回答：** GROUP BY 压缩行；窗口函数在保留结果行的同时计算组内排名、累计或前后差。

**深挖追问与回答：** 窗口排序通常需要临时表或 filesort。

## 15. ROW_NUMBER 与 DENSE_RANK 区别？

**核心回答：** ROW_NUMBER 永不并列；DENSE_RANK 同值并列且名次不跳号。

**深挖追问与回答：** 业务榜单要先决定同分是否并列。

## 16. LAG 在项目里做什么？

**核心回答：** 比较当前分群与前一名分群的平均倾向差。

**深挖追问与回答：** 排序方向决定差值符号，必须在输出中解释。

## 17. LEFT JOIN 为什么用于质量检查？

**核心回答：** 它保留左表全集，从而能用右表 NULL 识别缺失匹配。

**深挖追问与回答：** WHERE 条件写在右表列上可能把 LEFT JOIN 意外变成 INNER JOIN。

## 18. INNER JOIN 何时使用？

**核心回答：** 确认覆盖完整后，分析需要三表字段时用 INNER JOIN，使意图清晰。

**深挖追问与回答：** 质量检查阶段仍应使用 LEFT JOIN。

## 19. COUNT(*) 和 COUNT(column) 差异？

**核心回答：** COUNT(*) 计行，COUNT(column) 忽略 NULL；连接覆盖用两者差异识别缺口。

**深挖追问与回答：** 对可空字段使用 COUNT(column) 时不要误当总行数。

## 20. AVG(condition) 为什么可算比例？

**核心回答：** MySQL 布尔表达式返回 0/1，AVG 就是满足条件的比例。

**深挖追问与回答：** NULL 会被忽略，分母口径必须审查。

## 21. 如何处理 SQL 中的 NULL？

**核心回答：** 用 IS NULL、CASE 和明确过滤；不能用 = NULL。

**深挖追问与回答：** COALESCE 会改变含义，只在业务上确有默认值时使用。

## 22. 为何不用存储过程装载？

**核心回答：** 数据源是 CSV 与 pandas 产物，Python 更适合模式映射、文件核验和跨平台日志。

**深挖追问与回答：** 纯数据库生产环境可改用 LOAD DATA + 存储过程。

## 23. to_sql 有什么限制？

**核心回答：** 便利但不是最快；超大数据可能改用 LOAD DATA LOCAL INFILE。

**深挖追问与回答：** 本项目通过分块、重试和行数验证换取实现清晰。

## 24. 为什么全量刷新用 TRUNCATE？

**核心回答：** 本项目是可重建快照，TRUNCATE 快且避免重复。

**深挖追问与回答：** 生产增量不能直接套用，应使用 staging、主键 upsert 和水位线。

## 25. 事务能否覆盖 TRUNCATE？

**核心回答：** MySQL DDL 会隐式提交，因此这里依靠可重跑全量快照和末端验证，而非宣称完全原子。

**深挖追问与回答：** 更严格方案是装入 shadow tables 后 RENAME TABLE 原子交换。

## 26. 如何设计增量更新？

**核心回答：** 按批次时间或源版本写 staging，校验后用 INSERT ... ON DUPLICATE KEY UPDATE 合并。

**深挖追问与回答：** 需要删除语义时再加软删除或变更日志。

## 27. 如何防止 SQL 注入？

**核心回答：** 值参数使用 SQLAlchemy text 绑定；数据库名仅允许字母数字下划线。

**深挖追问与回答：** 表名和列名不能直接接受未经验证的用户输入。

## 28. 密码如何保护？

**核心回答：** .env 本地保存且被 Git 忽略，.env.example 只有占位值，日志掩码。

**深挖追问与回答：** 生产应使用 Secret Manager 和短期凭据。

## 29. 如何解释 ROC-AUC？

**核心回答：** 随机抽一名正例和负例，模型把正例排在前面的概率。

**深挖追问与回答：** AUC 不代表概率校准，也不直接等于业务收益。

## 30. 为什么校准差重要？

**核心回答：** 同一十分位平均预测与实际正例率的差能揭示概率偏高或偏低。

**深挖追问与回答：** 排序优秀的模型仍可能需要 Platt 或 isotonic 校准。

## 31. 为什么不计算 Accuracy 排名？

**核心回答：** 比赛指标是 ROC-AUC，概率排序是核心；Accuracy 依赖阈值。

**深挖追问与回答：** 业务决策需要结合成本选择阈值。

## 32. 高潜客户怎么定义？

**核心回答：** 沿用现有分群规则：业务模型预测位于训练参考分布前 20%。

**深挖追问与回答：** 规则优先级会覆盖后续条件，必须按代码顺序解释。

## 33. Infrastructure-Constrained 如何定义？

**核心回答：** 预测不低于中位数、无家庭充电且附近站点位于低四分位。

**深挖追问与回答：** 只有 2505 名训练客户，行动前要检查样本和执行成本。

## 34. 为何不把分群当因果结论？

**核心回答：** 分群来自相关特征和预测，未经过随机试验。

**深挖追问与回答：** 营销效果应通过对照组验证增量 lift。

## 35. 为何不能算 ROI？

**核心回答：** 数据没有触达成本、转化收入或真实购买记录。

**深挖追问与回答：** 可以设计 ROI 公式和所需字段，但不能填写虚构结果。

## 36. Python-SQL 对账为何设 1e-10？

**核心回答：** 当前指标是同一浮点数据上的均值和计数，理论差异应接近机器精度。

**深挖追问与回答：** 涉及 DECIMAL 舍入时应按业务精度放宽。

## 37. 如何检查数据漂移？

**核心回答：** 按 source_set 比较分布、类别比例和 PSI/KS，但测试集漂移不等于标签漂移。

**深挖追问与回答：** 上线还需按时间监控输入和性能。

## 38. 为什么模型指标允许 NULL？

**核心回答：** 并非每次实验都记录 Accuracy、耗时或逐折结果，NULL 表示未产出。

**深挖追问与回答：** 不能用 0 代替，否则会被误解为真实成绩。

## 39. 如何保证 SQL 输出可复现？

**核心回答：** 命名查询、固定源文件、固定分群规则、一键脚本和 CSV 日志共同约束。

**深挖追问与回答：** 数据库与依赖版本仍应记录。

## 40. EXPLAIN 重点看什么？

**核心回答：** type、possible_keys、key、rows、filtered 和 Extra。

**深挖追问与回答：** 估算 rows 不是实际耗时；必要时使用 EXPLAIN ANALYZE。

## 41. 为什么有索引仍可能全表扫描？

**核心回答：** 查询返回比例高或需要全表聚合时，扫描成本可能低于大量随机回表。

**深挖追问与回答：** 索引存在不等于必然使用。

## 42. 怎样优化窗口查询？

**核心回答：** 先过滤、先聚合缩小行数，再对小结果集开窗；为过滤和连接键建索引。

**深挖追问与回答：** 窗口本身的排序成本通常无法完全消除。

## 43. 如何验证索引有效？

**核心回答：** 对代表性查询比较 EXPLAIN、实际耗时与扫描行数，并观察写入开销。

**深挖追问与回答：** 只看索引列表不能证明收益。

## 44. 为什么公开包排除行级预测？

**核心回答：** 比赛代码虽已先在 Kaggle 公开，但原始/行级数据、模型和提交仍不适合进入 GitHub 作品包。

**深挖追问与回答：** 公开聚合指标和可复现代码即可展示能力。

## 45. 怎样向业务方解释两个模型分数？

**核心回答：** 0.945713 是竞赛最终融合 OOF；0.941993 是可解释业务分群模型 OOF。

**深挖追问与回答：** 两者回答的问题不同，不能只说一个“项目准确率”。

## 46. 项目最大的技术风险？

**核心回答：** 合成数据与竞赛特征可能无法迁移到真实用户；测试标签不可见。

**深挖追问与回答：** 需要真实时间外验证、校准和实验闭环。

## 47. 项目最大的 SQL 风险？

**核心回答：** 全量快照装载时间和 DDL 非原子，失败时可能留下部分状态。

**深挖追问与回答：** 生产化应使用 staging 表与原子换表。

## 48. 如果数据翻十倍怎么办？

**核心回答：** 优先批量加载、分区/列式分析引擎、增量计算和预聚合。

**深挖追问与回答：** 是否换技术栈取决于 SLA，而不是单看行数。

## 49. 如何为 Power BI 服务？

**核心回答：** SQL 导出稳定聚合 CSV，也可让 BI 只读连接到视图。

**深挖追问与回答：** 生产连接应限制权限并避免 BI 扫描原始大表。

## 50. 你在项目中独立做了什么判断？

**核心回答：** 把竞赛预测和业务分群分轨、拒绝虚构交易 KPI、用 OOF 入库并建立 Python-SQL 对账。

**深挖追问与回答：** 这些判断比单纯堆 SQL 语法更能说明数据治理能力。
